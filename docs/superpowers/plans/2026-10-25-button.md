# Button design and implementation plan

Status: approved with the final clarifications recorded below.

## Design

Evolve the existing Button in place into one reusable component with native
button or anchor semantics. Keep component code and CSS in `packages/ui-react`,
consume shared semantic tokens, and preserve the existing Tailwind 4 setup.
No dependencies, router integration, polymorphic API, or unrelated refactoring.

### Approach

Use an `href`-discriminated union and a shared content/style implementation,
with a small native-element rendering branch. Separate ButtonLink components
would duplicate the public styling contract; a polymorphic API would add
unnecessary complexity. The union is the recommended approach requested here.

### Public API

Shared options:

```ts
type ButtonAppearance = {
  variant?: "filled" | "outlined" | "bottom-border" | "text";
  icon?: ReactNode;
  iconPosition?: "start" | "end";
  radius?: CSSProperties["borderRadius"];
  color?: CSSProperties["color"];
  padding?: "normal" | "none";
  paddingX?: CSSProperties["paddingInline"];
  paddingY?: CSSProperties["paddingBlock"];
};
```

`ButtonProps` combines these options with native attributes through a union:
`href?: never` accepts button attributes; `href: string` accepts anchor
attributes. Omit native `color` in favor of the documented accent option.
Button-only attributes such as `disabled` and `form` are rejected on links.
Native anchor `type` remains a MIME-type hint, not a button behavior.
Callbacks receive the appropriate native element type.

Defaults: `filled`, icon at `start`, existing `rounded-lg` radius and `px-4 py-2`
padding. Default native buttons to `type="button"`; explicit submit is supported.
Existing consumers and tests do not rely on implicit submission. Merge `className` with component classes
and preserve `style`, with explicit radius/color props taking precedence over
their corresponding component custom properties.

Text-only and icon-plus-text retain ordinary React children. Icon-only usage
(no children) requires `aria-label` or `aria-labelledby` as a documented usage
contract, without an additional accessibility union. The icon slot is decorative and hidden from assistive technology;
SVG examples inherit `currentColor`, with a consistent slot size. Consumers
provide icons that use `currentColor`; do not rewrite arbitrary SVG internals.

```tsx
<Button onClick={save}>Save</Button>
<Button variant="outlined" icon={<ArrowIcon />} iconPosition="end">
  Continue
</Button>
<Button variant="text" icon={<CloseIcon />} aria-label="Close" />
<Button href="/contact" variant="bottom-border" padding="none">
  Contact
</Button>
<Button color="#6750a4" radius="9999px">Explore</Button>
```

### Appearance and interaction

- Filled uses primary as its background; other variants use semantic foreground
  as their default accent. Borders inherit the relevant foreground, including
  the bottom-only border. Transparent variants have no background fill.
- Custom `color` means filled background or transparent-variant text/border.
  Match Switch/SegmentedControl's opaque absolute CSS color contract; transparent
  colors and variable references are outside this iteration's supported contract.
- Use colocated CSS and feature detection for `color-mix()` and
  `contrast-color()`. Filled text uses contrast-derived black/white for its
  actual resting/hover background, correcting the documented dark contrast gap.
  Engines without these capabilities use a readable semantic foreground/background
  pair for filled buttons and semantic accents for transparent variants.
  No global primary-token changes affect other components.
- Hover lightly mixes the relevant color toward white. Keep the mix small and
  verify default text contrast against both background and surface in both modes.
  Custom transparent accents must be chosen for their surrounding surface;
  document and demonstrate accessible examples, rather than promise contrast for
  every caller-supplied color. Filled text contrast adapts to its hover background.
- Use a subtle semantic `:focus-visible` box-shadow, color transitions, and
  reduced-motion handling. Native disabled buttons suppress hover/callbacks and
  receive subdued styling. Links stay native navigable anchors; there is no
  synthetic disabled-link API.
- Use Tailwind for layout and spacing, allow content wrapping at narrow widths,
  and retain visible keyboard focus with normal and zero padding.
