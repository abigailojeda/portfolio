## Focused design

### Public API

Export `Switch`, `SwitchProps`, and `SwitchState` through the component barrel
and the existing library entry point.

```tsx
type SwitchState = {
  label: string;
  icon?: ReactNode;
};

<Switch
  aria-label="Notifications"
  checked={enabled}
  onCheckedChange={setEnabled}
  uncheckedState={{ label: "Off" }}
  checkedState={{ label: "On" }}
  presentation="text"
/>;
```

- Required: `checked: boolean`, `onCheckedChange: (checked: boolean) => void`,
  `uncheckedState`, `checkedState`, and exactly one of `aria-label` or
  `aria-labelledby`, using SegmentedControl's existing naming convention.
- Optional: `disabled`, `id`, `className`, `color: CSSProperties["color"]`, and
  `presentation: "text" | "icon-text" | "icon"` (default `"text"`).
- State labels are required nonempty strings, including in icon-only mode.
  Icon-only props require an icon for both states through the public type.
  Icon-and-text mode permits optional icons independently for each state.
- Icons use `ReactNode` slots and inherit `currentColor`. They are decorative
  within the named switch; consumers must supply noninteractive icon content.
- No internal selection state, theme API, storage, application behavior, or new
  dependencies. A declined parent update leaves the rendered state unchanged.

### Semantics and interaction

Use one native `input type="checkbox" role="switch"` within a visual label.
The input owns checked state, disabled behavior, focus, and change events.
Its accessible name stays constant across state changes; assistive technology
announces the boolean state. Hide the visual state content from the accessibility
tree to avoid duplicating or changing the control's name.

Clicking anywhere on the control toggles the boolean, including the currently
highlighted half. Tab focuses one input; Space toggles it. Retain native checkbox
keyboard behavior without custom Enter, arrow-key, drag, or focus-management logic.
Call `onCheckedChange` once per native user change with the requested boolean;
controlled prop updates do not call it.

Alternatives considered: two radios would reproduce SegmentedControl's selection
interaction; a button with switch ARIA would require more explicit state wiring.
The native checkbox best matches the requested binary interaction.

### Visual behavior

Use an outlined rounded surface containing two equal positions and one rounded
highlight/thumb that slides between them. Both state contents stay visible when
their presentation includes them; the active content uses contrasting foreground.
Reuse semantic surface, border, foreground/background, and muted roles and the
existing Tailwind scales. Keep a minimum 44px interactive height, constrain width
to its container, and allow long text to wrap.

Use restrained transform/color transitions, respecting reduced motion, subtle
hover, and disabled opacity/cursor. Provide a component-local `:focus-visible`
border/box-shadow treatment; do not copy SegmentedControl's focus exception.

Match SegmentedControl's optional opaque absolute CSS accent contract, native
`contrast-color()`/`color-mix()` feature detection, and semantic fallback.
Keep necessary custom CSS colocated. Reuse actual shared light/dark tokens;
Minimal/Glass integration remains deferred.

## Review focus

- The whole control toggles; visual halves are not separate selection targets.
- Accessible naming remains stable with icon-only content and repeated instances.
- A parent declining an update leaves both native state and visual position intact.
- Unequal/long labels fit equal positions without clipping at narrow widths.
- Accent fallback, light/dark contrast, and subtle keyboard focus remain usable.

Implementation stays on the existing clean `feat/toggle-switcher` branch.
No portfolio integration, unrelated refactoring, or automatic commits.
