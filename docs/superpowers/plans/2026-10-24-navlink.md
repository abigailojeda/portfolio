## Focused design

### API and semantics

Export `NavLink` and `NavLinkProps` from `packages/ui-react`.
Use standard typed anchor props and children, with required `href: string`
and optional `variant: "simple" | "underline"` (default `"simple"`). Merge
consumer `className` with component classes. Preserve native click handlers,
attributes, accessible naming, browser navigation, and keyboard behavior.

```tsx
<NavLink href="#home" aria-current="location">Home</NavLink>
<NavLink href="#journey">Journey</NavLink>
<NavLink href="/projects" variant="underline" aria-current="page">
  Projects
</NavLink>
```

Native `aria-current` is the single source of active styling: omitted or false
means inactive; a current value means active. Consumers choose `page` for the
current page or `location` for the current section. No separate active state,
route matching, click-driven selection, state hook, or router dependency.
The consumer supplies meaningful text or an accessible name as for any anchor.

An anchor best fits navigation and preserves open-in-new-tab/context-menu
behavior. A button would have incorrect navigation semantics; a router adapter
would add an unrequested dependency and integration contract.

### Visual behavior

- **Simple:** compact text links matching the first reference. Inactive text
  uses muted foreground; hover and current links use foreground. No pill,
  background panel, or underline. Keep text weight stable to avoid layout shifts.
- **Underline:** text with a reserved underline beneath it. No visible line at
  rest; hover reveals a subdued line, and current links show a stronger solid
  foreground line, matching the second reference. Reserve space so states do
  not move the surrounding layout. This line identifies the current destination,
  rather than the momentary CSS `:active` pressed state.
- Use the existing semantic tokens and Tailwind CSS 4. Keep necessary pseudo-
  element selectors in colocated CSS; do not create tokens or shared abstractions.
- Visible keyboard focus uses a subtle component-local rounded box-shadow or
  border without a prominent outline. Focus remains distinguishable on a current
  link and in both variants. Color/opacity transitions are restrained and respect
  reduced motion. Labels wrap at constrained widths; containers own link spacing.
- Inherit existing light/dark scopes. No theme prop, visual-style integration,
  disabled-link API, icons API, or portfolio navbar in this scope.

- Ordinary links retain browser navigation and consumer event behavior.
- Both variants keep visible keyboard focus on inactive and current links.
- Underlines do not change link dimensions or cause layout shifts between states.
- Long labels wrap and both color modes use the existing shared semantic tokens.
